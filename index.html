Bagian 01

Latar Belakang

Dalam manajemen jaringan dan telekomunikasi modern, proses pemindaian keamanan — seperti vulnerability assessment dan packet sniffing — kerap harus memproses jutaan baris log traffic setiap harinya. Volume data tersebut menghasilkan tekanan komputasi yang sangat besar pada sistem.

Metode pemrosesan sequential konvensional — di mana satu core memproses satu baris data dalam satu waktu — seringkali memicu bottleneck yang signifikan, sehingga menunda deteksi anomali dan berpotensi membahayakan keamanan jaringan secara keseluruhan.

💡
Solusi yang Diusulkan

Proyek ini memanfaatkan modul multiprocessing bawaan Python untuk mendistribusikan beban kerja inspeksi log ke seluruh logical core yang tersedia, sehingga pemrosesan berlangsung secara konkuren dan paralel — bukan lagi satu-per-satu.

Bagian 02

Desain Arsitektur Sistem

Beban pemrosesan log didistribusikan secara merata ke seluruh core logical yang tersedia pada mesin. Antrean data besar dipecah menjadi beberapa segmen, lalu setiap segmen dieksekusi secara konkuren oleh Worker Process yang terpisah melalui multiprocessing.Pool.

Keunggulan Arsitektur Paralel

Setiap Worker Process berjalan independen di memori terpisah, memanfaatkan multiple CPU core secara penuh — tidak terbatas oleh Global Interpreter Lock (GIL) seperti halnya threading.

Bagian 03

Analisis Performa

Pengujian dilakukan dengan mensimulasikan inspeksi sejumlah batch log jaringan. Setiap entri log dianalisis untuk mendeteksi indikator anomali keamanan. Hasil pengukuran latensi dibandingkan antara pendekatan sequential dan paralel.

Metrik Sequential (1 Core) Paralel (Multi-core) Kesimpulan
Jumlah Core 1 Core N Core (semua tersedia) Tergantung Mesin
Strategi Pemrosesan Baris per baris (satu per satu) Chunk paralel konkuren ✔ Paralel Lebih Efisien
Latensi pada Data Besar Tinggi (linear terhadap N data) Rendah (dibagi N core) ✔ Paralel Lebih Cepat
Risiko Bottleneck Tinggi Sangat Rendah ✔ Paralel Lebih Aman
Skalabilitas Tidak skalabel Linear terhadap jumlah core ✔ Paralel Lebih Baik
Overhead Minimal Ada (proses spawn) ⚠ Sequential Lebih Ringan
⚠️
Catatan Penting: Overhead vs. Speedup

Pendekatan paralel membawa overhead berupa waktu inisiasi proses (spawn time). Untuk dataset kecil, overhead ini bisa membuat pemrosesan paralel justru lebih lambat. Keunggulan paralel baru terlihat signifikan pada dataset besar (ribuan hingga jutaan entri log).

Bagian 04

Instruksi Eksekusi

Ikuti langkah-langkah berikut untuk menjalankan simulasi perbandingan performa sequential vs. paralel secara lokal di mesin Anda.

  • Pastikan Python 3.x Terinstall

    Unduh dan pasang Python 3.8 atau lebih baru dari python.org. Modul multiprocessing sudah termasuk di Python Standard Library, tidak perlu instalasi paket tambahan.

  • Clone atau Unduh Repositori

    Buka terminal / command prompt lalu jalankan perintah berikut untuk mengunduh kode sumber dari GitHub:

  • Navigasi ke Direktori Proyek

    Masuk ke folder repositori yang sudah diunduh, pastikan file main.py tersedia di direktori aktif Anda.

  • Jalankan Simulasi

    Eksekusi skrip utama dengan perintah di bawah. Program akan secara otomatis menjalankan kedua pendekatan dan menampilkan perbandingan latensi di terminal:

Terminal  —  bash / cmd / powershell

# 1. Clone repositori
git clone https://github.com/Lifyhzz/Lifyhzz-Parrallel-Network-InspectionV3.git
cd Lifyhzz-Parrallel-Network-InspectionV3

# 2. Jalankan simulasi
python main.py
